llmhost 0.6.0-beta22 — Release Notes (публичный тест, 2026-11-12)
=================================================================

WHAT'S NEW IN BETA22 (ENGLISH SUMMARY)
  The full-screen interface now looks like one product: the header,
  the key bar and the cursor row no longer mix inverse video with
  colored spans (each colored span used to cancel the inverse mid-line,
  which read as a different font on every other word). Inverse is now
  reserved for solid surfaces — screen titles and the full-width
  cursor row (rendered through a new plain() helper that strips ANSI
  before painting); the key bar lost its bold/inverse chips; bold is
  gone from the chrome entirely; the rare glyphs ⏹/✗ are replaced
  with text/×. A translation-coverage audit closed 65 holes — an
  English-locale terminal no longer sees Russian fragments in the key
  bar, confirmation dialogs, image-slot statuses or lhctl image pages.
  Reliability pass on the download-stop feature: a race in the cancel
  flag lifetime (a stop landing in the booking window or on early
  image-plan exits could leave the flag armed, instantly killing the
  NEXT download as "stopped") is fixed by clearing the flag at
  booking; the image pipeline got an earlier cancel checkpoint; the
  ANSI-stripping helper no longer lets non-CSI escape bytes through.
  The full text below is in Russian — the canonical language of the
  project.


llmhost 0.6.0-beta21 — Release Notes (публичный тест, 2026-11-12)
=================================================================

WHAT'S NEW IN BETA21 (ENGLISH SUMMARY)
  Downloads can now be stopped properly: DELETE /v0/pull, the new
  «lhctl pull stop» command and Ctrl-X anywhere in the full-screen
  interface. The running curl is killed within a quarter of a second,
  the transfer ends in a distinct stopped state, and the partial .part
  file stays on disk — repeating the same pull resumes from where the
  stop happened. While the stop is propagating, GET /v0/pull reports
  "stopping": true. Planner fix for the llama4 family (Llama-4 Scout
  and friends): those GGUF files carry no sliding-window metadata, so
  the engine derives it for the architecture itself (8192-token
  window, every fourth layer global); llmhost now derives the same,
  and the KV estimate stops counting every layer at full context —
  for a 131k context the analytic KV drops from ~13 GiB to ~4 GiB,
  the model card keeps learning instead of discarding every
  measurement. The full text below is in Russian — the canonical
  language of the project.


llmhost 0.6.0-beta20 — Release Notes (публичный тест, 2026-11-11)
=================================================================

WHAT'S NEW IN BETA20 (ENGLISH SUMMARY)
  Exact engine telemetry is now exposed everywhere: /v0/metrics carries
  per-model decode and prefill throughput, speculative acceptance and
  token counters taken straight from the engine's own /metrics
  (llmhost_engine_* families). lhctl metrics [-w sec] renders a live
  table with an instantaneous-tokens-per-second sparkline; the TUI gets
  a metrics screen (key m) sampling deltas every two seconds. Per-model
  thinking mode (thinking-mode = auto/on/off) forces --reasoning on the
  child — switched via lhctl thinking, the T key in the model card or
  POST /v0/models/thinking. Planner fix: a manual MoE-cache grant
  without a context pin no longer buys cache with context — the shape
  and its context are built without the arena, the grant is applied to
  the ready shape or honestly dropped (previously the arena silently
  cut the context, e.g. 17408 instead of 131072). Engine prebuilds:
  llama.cpp b12246 with the upstream MoE-cache line merged (parallel
  CPU-side cache-miss compute, LRFU cache policy, the speculative draft
  no longer poisons the MoE cache). The full text below is in Russian —
  the canonical language of the project.


НАЗНАЧЕНИЕ
llmhost предназначен для локального запуска больших языковых моделей
(LLM) на вашей машине под Linux: приватность и работа в автономной
среде — тексты не покидают компьютер. Это обёртка над ванильным
llama.cpp (пребилды b11963: CUDA 12.8 с SASS sm_120a под Blackwell +
Vulkan, без форков и патчей), которая, используя автоматически
вычисляемые параметры запуска, повышает утилизацию системных ресурсов
и скорость инференса. Графический интерфейс отсутствует намеренно:
взаимодействие через API, терминал и браузер.

СТАТУС: ПУБЛИЧНАЯ БЕТА
Основной испытанный путь — Ubuntu (x86-64) + NVIDIA (CUDA). На других
конфигурациях поведение может отличаться от испытанного: устанавливайте на
машины, потеря которых не критична, и присылайте log.txt при
странности (см. раздел «ДИАГНОСТИКА ПРОБЛЕМ»).

ТРЕБОВАНИЯ
  Linux x86-64 (пребилды llama.cpp тоже только x64)
  Разработка и тестирование ведутся на Ubuntu; на других дистрибутивах
    полноценная работоспособность не гарантируется (тестирование не
    проводилось)
  systemd user-сессия — для службы (без неё: --no-start и ручной запуск)
  GPU: NVIDIA (CUDA 12.8) — основной испытанный путь; Vulkan —
    экспериментальный (на стенде не замерен, работоспособность не
    гарантирована)
  ~4 МБ под бинари + ~0,8 ГиБ движок + место под модели
  Интернет при первом запуске: скачается движок и модели

УСТАНОВКА — ОДНА КОМАНДА
  curl -fsSL https://github.com/bkisonka/llmhost/releases/latest/download/install.sh | sh

  Установщик проверит SHA256 тарболла (fail-closed), поставит llmhostd,
  lhctl и manifest.json в ~/.local/lib/llmhost (симлинк lhctl в
  ~/.local/bin с записью в PATH), спросит каталог моделей и запишет его
  в llmhost.conf, поставит systemd user unit с автоподъёмом и движок
  (cuda12 при живом nvidia-smi, иначе vulkan).
  Root не нужен и sudo не используется: всё живёт в домашнем каталоге
  (бинари ~/.local/lib/llmhost, симлинк ~/.local/bin, user unit,
  данные ~/.local/share/llmhost).
  Откуда что качается: движок llama.cpp — только из официальных релизов
  llama.cpp (github.com/ggml-org/llama.cpp), SHA256 по манифесту,
  расхождение — отказ; модели — с HuggingFace, тоже со сверкой SHA256.
  Других сетевых источников нет. Качать движок через приложение не
  обязательно: скачайте релиз llama.cpp сами и распакуйте его в
  <данные>/engine/cuda12/ (или engine/vulkan/) — демон сам увидит сборку
  как установленную; произвольный бинарник из любого места — ключом
  llama-server в llmhost.conf; установщик умеет ставить без движка
  (--no-engine).
  Обновление — повторный запуск той же команды: демон останавливается,
  бинари заменяются, служба поднимается; данные и модели не трогаются.
  Без systemd: --no-start (запуск вручную ~/.local/lib/llmhost/llmhostd).

ОСНОВНЫЕ ВОЗМОЖНОСТИ
  - Два режима: классический (один слот) и harness — отдельный процесс
    llama-server для каждой модели: несколько моделей резидентно,
    занятая запросом модель не выселяется, пробуждение из очереди с
    TTL; вытесненные по простою сохраняют KV-состояние на NVMe и
    просыпаются быстрее; эмбеддинг-модели, vision (mmproj подключается
    автоматически)
  - Multi-GPU: размещение с учётом скорости карт; не помещающаяся
    модель распределяется тензорным сплитом по пулу, MoE-эксперты — в
    RAM полностью или частично (--n-cpu-moe); перед загрузкой тяжёлой
    модели резиденты выгружаются автоматически
  - Веб-дашборд и lhctl (TUI: реестр, каталог, чат, движок), OpenAI-порт
    /v1, контрольный API /v0, метрики Prometheus (/v0/metrics),
    именованные токены
  - Устойчивость прокси: некорректные OpenAI-запросы отклоняются с
    кодом 400 до запуска модели, зависший upstream — 504 через 300 с
  - Планировщик: SWA-окна из GGUF-метаданных, профили VRAM-следа по
    форме запуска (после фактической загрузки план адаптируется),
    точные объёмы MoE-экспертов и CPU-тензоров из тензорного списка
  - Единый конфиг llmhost.conf ([general] + per-model), применяется на
    лету

НОВОЕ В BETA21 (против beta20)
  Штатная остановка скачиваний и честная аналитика llama4:
  - Остановка идущего скачивания: DELETE /v0/pull, «lhctl pull stop»
    и Ctrl-X в полноэкранном интерфейсе (с любого экрана — строка
    прогресса общая). curl прерывается на ближайшем тике прогресса,
    скачивание доезжает до отдельного состояния stopped, недокачанный
    .part остаётся на диске — повторный pull продолжает с места
    останова. Пока остановка расходится, /v0/pull несёт
    "stopping": true; в интерфейсе строка прогресса показывает
    «остановка…». Работает для обоих видов скачиваний (llm и
    image-модели) — поток загрузки один.
  - Аналитика llama4-семейства (Llama-4 Scout и соседи): у этих GGUF
    нет ключей sliding-window, движок выводит геометрию для арки сам
    (окно 8192, каждый 4-й слой глобальный) — планировщик теперь
    выводит так же. Оценка KV перестала считать все слои полным
    контекстом: на ctx 131k аналитика падает с ~13 ГиБ до ~4 ГиБ,
    план честно отдаёт освободившееся место блокам экспертов на
    карте, а профиль формы впервые записывается (прежде замер
    отбрасывался как «разошёлся»).

НОВОЕ В BETA20 (против beta19)

  - Метрики движка в /v0/metrics: скорости декода и префилла, приём
    спекуляции, токены и секунды декода по-модельно — из /metrics живых

  - Пер-модельный thinking-mode (auto/on/off): форс --reasoning ребёнку
    (auto — движок сам детектит thinking по шаблону). Переключение —
    lhctl thinking <модель> [auto|on|off], клавиша T карточки,
    POST /v0/models/thinking; строка Thinking в карточке модели.
  - Фикс планировщика: ручной грант кэша MoE без пина контекста больше
    не покупает кэш ценой контекста — форма и контекст строятся без
    арены, грант прикладывается к готовой форме или честно снимается с
    логом (прежде арена молча резала контекст: Flash-Next получал
    ctx 17408 вместо 131072). С пином контекста — прежнее поведение:
    пин держит контекст, гейт снимает кэш при нехватке.
  - Пребилд движка b12246: кэш-линия MoE вошла в апстрим — параллельный
    CPU-счёт промахов кэша (--moe-cache-cpu-share), LRFU-политика кэша,
    спекулятивный черновик больше не вытесняет MoE-кэш ствола.

НОВОЕ В BETA19 (против beta17)
  Кэш MoE стал управляемым с гарантиями, простоявшие слоты просыпаются
  быстро, планировщик объясняет свои решения:
  - Парковка KV-состояния слотов на NVMe (harness): перед остановом по
    простою состояние сохраняется на диск, при пробуждении возвращается
    — слот не переплачивает перепрефилл (возврат с NVMe на порядок
    быстрее повторного прогона промпта). Парковка видна в lhctl status
    и в API.
  - Гейт «пин контекста × арена кэша»: форма, влезающая на карту только
    без кэша, честно едет без него — раньше лестница сначала ловила
    OOM-ы и лишь потом деградировала. В лестнице появился шаг «та же
    форма без кэша»; размер кэша задаётся per-model (moe-cache-mib в
    секции модели) и через API (/v0/models/cache), авто-подбор
    учитывает параллельный CPU-счёт промахов.
  - Ноты планировщика в чате: урезанная против плана форма (срезан ctx,
    снят кэш, часть слоёв уехала в RAM) доезжает до клиента диагнозом и
    вариантами (lhctl vision, lhctl ctx) прямо в ответе.
  - CPU-потоки ребёнка: ключ [general] threads (-t), 0 — дефолт движка.
    Физические ядра бьют SMT-дефолт на формах с экспертами в RAM.
  - Ветки движка явным списком в TUI (F9 → F5): выбор cuda-ветки без
    правки конфига; новые ветки достраиваются манифестом из ассетов
    релиза автоматически.
  - Фиксы: деградация лестницы наследует размещение экспертов — MoE
    больше не роняется в плотный сплит; явный путь llama-server
    наследует вид сборки от engine-build. Затравка манифеста — b11963.

НОВОЕ В BETA15 (против beta14)

  - Кэш горячих MoE-экспертов: ключ moe-cache-mib задаёт размер арены;
    без значения размер подбирается автоматически — из замеренной пары
    скоростей (кэш/база) выводится локальность модели: окупает ли

  - Vision стал переключателем: vision-режим в карточке TUI и

    цеплял чужую проекцию и приводил лестницу загрузки к
    последовательности OOM-ошибок, а ручные проекции формата
    «ствол-mmproj» не находились вовсе — vision не работал без

  - Запасная карта под черновик и экспертов: ключи draft-card /
    expert-card (harness) — куда ставить выгруженные кусочки, когда

  - TUI: действия в карточках больше не спорят с перерисовкой списка

НОВОЕ В BETA14 (против beta13)
  Подбор draft-моделей стал разборчивым, чёрные списки переживают рестарт:
  - MTP-модуль прицепляется только «своей» модели: имя модуля
    (mtp-<имя><квант>) обязано быть префиксом имени основной модели.
    Прежде в плоской папке модулей брался первый попавшийся с совместимым
    словарём — чужая голова проходила проверку меты, приводил к падению
    дочернего процесса llama-server и нарушал загрузку повторными
    попытками (наблюдено фактически: три чужих draft за три загрузки
    одной небольшой модели).
  - Встроенный MTP (nextn-тензоры в самом GGUF — Qwen3.6/3.5-MTP,
    Qwen3.8, GLM) перекрывает файловые авто-головы во всех путях
    загрузки (раньше один из трёх перекрытия не имел); в журнале честно
    пишется «встроенный MTP», когда спекуляция едет на нём.
  - Вердикты по draft («движок не смог его загрузить», «приём ниже
    порога») сохраняются в model_profiles.json и переживают рестарт
    демона; при смене релиза движка стираются вместе с замерами. Раньше
    первая же загрузка после рестарта повторяла ту же ошибку.
  - Затравка манифеста движка обновлена до b11897 — в согласии с
    установленным движком; проверка сверяет пин затравки с фактическим.

НОВОЕ В BETA13 (против beta12)
  Релиз безопасности: итог сплошного аудита кода (память, переполнения,
  HTTP-поверхность, целостность скачиваний, спавн процессов). Поведение,
  API и пин движка (b11541) не изменились — сузилась площадь атаки и
  закрыты накопители long-running демона:
  - Лимиты тела запроса работают при всех типах передачи: httplib
    проверял его только на ветке Content-Length, а chunked-тело
    накапливалось в памяти ещё до авторизации (DoS до OOM). Локальный
    патч вендора; превышение — честный 413
  - OpenAI-порт наружу — только /v1* и /health (GET/POST): раньше прокси
    пробрасывал ребёнку любой путь с любым методом, подставляя его
    собственный ключ, и владение /v1-токеном давало всё админ-API
    llama-server (unload/load чужих моделей, /props с путями и настройками)
  - «model» из /v1 резолвится строго через реестр: произвольный путь
    вида /чужой/файл.gguf больше не заставляет демона читать и грузить
    в VRAM что попало — пути вне реестра остались только админскому
    /v0/load
  - Четыре накопителя памяти: RAII-билет очереди пробуждения (раньше
    потерянный тикет навсегда занимал место и множил «очередь полна»),
    кардинальность метрик по клиентским именам моделей (потолок, сверха
    — в один бакет), LRU-штампы только известным id, зависание стрима
    на закрытии канала; фантомные Error-слоты не заводятся
  - Гонка писателей llmhost.conf закрыта ([general], per-model секции и
    MTP-включение — под одним замком, tmp с уникальным именем):
    concurrent правки больше не теряют секции молча
  - Целостность скачиваний — fail-closed: SHA256 из HF стал
    извлекаться из фактического формата API (прежде хеш не сверялся
    никогда), крупные файлы без хеша не качаются, «уже скачанный»
    перепроверяется по хешу, пустой sha256 в манифесте — отказ,
    хост ассетов фиксирован, объём распаковки проверяется до, а не
    после разархивирования
  - Бинарь движка опрашивается (--version) только если его нельзя
    подменить извне (владелец/права); llama-server больше не ищется
    в текущей директории через пустой сегмент PATH; api_tokens.json
    создаётся сразу 0600 (окно umask и предсказуемый .tmp закрыты)
  - Заголовок GGUF: скаляры обрезаются потолком на входе, оценки VRAM
    — насыщающая арифметика: враждебный .gguf не вешает планировщик
    и не рисует ложное «влезет»; [general] ctx получил верх (2097152)
  - Markdown-рендер чата: потолок рекурсии и вычищение control-байтов
    из RTF; дашборд закрыт от встраивания (frame-ancestors 'none',
    X-Frame-Options); текст внутренних ошибок — только в журнал
  - Прокси: пулы воркеров явные (долгие стримы и ожидание будилки
    раньше голодали порт при пуле из ядер CPU); при остановке демон
    дожидается install/pull/bench (потолок 10 с, в рамках
    TimeoutStopSec)
  - Молчаливая смерть исключена: фатальные сигналы (SIGFPE/SIGSEGV/SIGBUS/
    SIGILL) пишут отпечаток в log.txt и stderr перед выходом — «приложение не
    запускается» различимо по последней строке журнала (core и trap-строка
    dmesg сохраняются)
  Проверено: ASAN-сборка 13/13; сценарные тесты классики и harness —
  50/50 и 41/41; живой сервер на этом коде прошёл полный цикл
  load→чат→стрим→unload — 18/18. Ручные e2e (api, harness-multiuser) —
  контракт чист; единственные незелёные проверки зависят от фикстур
  песочницы (thinking-модели нужен бюджет токенов больше 16; TTL-504 не
  воспроизводится без реального VRAM-конфликта) и на живом сервере
  проходят.

ОСОБЕННОСТИ ПОВЕДЕНИЯ (сделано намеренно)
  - После смены движка замеренные профили стираются: первые загрузки
    консервативнее (аналитика), через одну-две загрузки план снова
    точный. Если модель «вдруг медленно» — перезапустите демона.
  - «Спекуляция отключена» в журнале — сработал контролёр или
    failover, а не поломка: скорость не опускается ниже базовой.
  - Контекст/форма модели выбираются автоматически; ручные значения —
    lhctl ctx и per-model секции llmhost.conf. [general] ctx — пол
    плана, а не пин: план не опустится ниже, но может поднять; жёсткий
    пин — только per-model.

ОГРАНИЧЕНИЯ
  - Только x86-64; на arm64 установщик откажет с сообщением
  - Графический интерфейс отсутствует: API + lhctl + веб-дашборд;
    удаление моделей — немедленно и безвозвратно (корзины в headless-
    среде нет)
  - NVIDIA старше Turing — только Vulkan-сборка движка (эксперимент.)
  - Пакетов deb/rpm нет: curl|sh или тарболл руками

ПРИВАТНОСТЬ И БЕЗОПАСНОСТЬ
  Всё работает локально; наружу уходят только запросы к HuggingFace при
  скачивании моделей и к GitHub при установке/обновлении. API по
  умолчанию слушает localhost и закрыт обязательным Bearer-ключом
  (token.txt, 0600); при привязке не на localhost (openai-bind 0.0.0.0 —
  внешняя служба) ключ принудителен. CORS — только доверенные источники.
  С beta13: OpenAI-порт обслуживает только /v1* и /health; размер тела
  запроса ограничен при всех типах передачи; сравнение токенов — за
  постоянное время; скачанные модели по умолчанию сверяются по SHA256,
  крупные файлы без проверочного хеша не качаются вовсе.

ДИАГНОСТИКА ПРОБЛЕМ
  journalctl --user -u llmhostd -f (и log.txt в data-dir, ротация
  1 МиБ) — первая информация для отчёта: версии, выбор автоматических
  параметров и причины отказов. Справка: lhctl status, lhctl --help,
  README.md (раздел «Устранение неполадок»).
